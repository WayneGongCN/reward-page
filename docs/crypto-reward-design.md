# BTC/USDT 二维码赞赏设计

## 目标

BTC 和 USDT 复用现有二维码赞赏渠道。前端只负责展示图片、公开地址和双语文案，不连接钱包、不查询链上数据，也不根据币种或网络执行不同逻辑。

当前没有真实二维码与公开地址，因此生产配置暂不启用 `btc`、`usdt`。自动化测试使用明确的测试值验证完整能力；真实素材到位后只需更新配置和静态资源。

## 配置协议

共享渠道支持可选的 `copyValue`：

```ts
interface SharedRewardChannel {
  id: string
  qrImage: string
  copyValue?: string
}
```

`copyValue` 用于展示和复制公开文本。解析器去除首尾空白；字段一旦出现就必须是非空字符串。解析器不判断 BTC、Lightning、TRC20 或 ERC20 格式，使协议保持通用并避免前端产生不完整的链上校验假象。

虚拟币渠道约定使用 `btc`、`usdt` ID，并排在当前渠道末尾。两种语言必须提供相同 ID 的 `name`、`alt` 和可选 `description`。链或网络名称写在 `description`，不进入共享类型。

## 页面行为

配置 `copyValue` 的卡片在二维码与说明下显示：

1. 本地化的“钱包地址”标签。
2. 可换行、可手动选择的完整公开地址。
3. 本地化的复制按钮和 `aria-live` 状态提示。

复制优先调用 Clipboard API；调用不可用或失败时，回退到用户点击触发的传统复制命令。两种方式均失败时显示“复制失败，请手动复制”，地址仍完整保留。未配置 `copyValue` 的微信、支付宝和 Buy Me a Coffee 卡片不渲染以上区域。

URL 参数继续使用通用渠道 ID，例如 `?channels=btc,usdt`。页面按配置顺序展示，参数顺序不改变卡片顺序。复制动作不新增分析事件，地址也不会进入现有 GA 参数。

## 发布检查

- 将真实二维码放入 `public/assets/`，并用真实公开地址替换设计占位符。
- 分别在 `zh-CN`、`en` 中补齐 BTC/USDT 名称、替代文本和网络说明。
- 使用独立设备扫描二维码，逐字符确认解析结果与 `copyValue` 完全一致。
- 在目标钱包收款页确认币种、网络和地址；网络差异由素材提供方负责确认，前端不推断。
- 验证完整页、嵌入页、`?channels=btc,usdt`、移动端换行及复制成功/失败状态。
- 运行 `pnpm test`、`pnpm typecheck` 和 `pnpm build` 后方可发布。

钱包地址和二维码属于公开内容。任何私钥、助记词、密码、Token 或交易所 API 密钥都不得进入配置、源码、日志或分析事件，喵~
